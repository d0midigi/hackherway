ScrollSpy + Accordion

    Getting Started

    Welcome to the tutorial. This page demonstrates a scrollspy navigation system with a 3-level accordion. Grandparents expand to show parents, parents expand to show children. As you scroll, the sidebar highlights the active section and auto-expands its ancestors.

    Click any caret to expand or collapse a level. Click a link to smoothly scroll to that section. The active section is tracked via IntersectionObserver.

    Tip

    Try scrolling and clicking carets. The accordion only allows one branch open at a time per level, keeping the sidebar clean.

    Installation

    Before we begin, make sure you have the prerequisites installed. This tutorial assumes basic familiarity with HTML, CSS, and JavaScript.

    Overview

    The package is distributed via npm and CDN. Choose the method that fits your workflow. Both methods expose the same API.

    Using NPM

    The recommended way to install is via your package manager of choice.

    # Install via npm npm install "tutorial-package" # Or with yarn yarn add "tutorial-package"

    Using CDN

    For quick prototyping, you can also load directly from a CDN.

    <script src="https://cdn.example.com/package.js"></script>

    Verification

    After installation, verify everything is working by running the built-in health check.

    import { checkHealth } from 'tutorial-package'; checkHealth().then(status => console.log(status));

    Common Issues

    If you see a module resolution error, ensure your bundler is configured to handle ES modules. For webpack, add the resolve.alias configuration.

    Troubleshooting

    Clear your node_modules and lock file, then reinstall. If the issue persists, check the peer dependency versions match your environment.

    Core Concepts

    Understanding the fundamental concepts is essential before diving into implementation details. This section covers the architecture and design patterns.

    Architecture

    The system follows a modular architecture where each component is self-contained and can be used independently.

    Modular Design

    Every module exports a single responsibility. Dependencies are injected rather than hard-coded, making testing and mocking straightforward.

    Layered Architecture

    The codebase is organized into three layers: presentation, business logic, and data access. Each layer communicates through well-defined interfaces.

    Lifecycle

    Every component goes through a well-defined lifecycle: initialization, mounting, updating, and destruction.

    Lifecycle Hooks

    Hooks are provided at each stage for custom logic. Register them during component definition.

    const component = new Component({ onMount: () => console.log('Mounted!'), onUpdate: (data) => console.log('Updated:', data), onDestroy: () => console.log('Clean up') });

    Cleanup Patterns

    Always unregister event listeners and cancel pending requests in the destroy hook to prevent memory leaks.

    Reactivity

    The reactivity system uses Proxies to intercept property access and mutations.

    Proxy-Based Tracking

    When a reactive property is read inside a computed function, that function is registered as a dependency. On mutation, all dependents are notified.

    Computed Values

    Computed properties are cached and only re-evaluate when their dependencies change. This avoids unnecessary recalculation.

    Components

    Components are the building blocks of any application built with this system.

    Defining Components

    A component is defined as a plain object with specific properties.

    Component Structure

    The render function returns the virtual DOM representation. Props define the external interface.

    export default { name: 'Button', props: ['variant', 'size'], render(props) { return `<button class="btn btn--${props.variant}">${props.children}</button>`; } };

    Registration

    Register components globally or locally. Global registration makes them available everywhere without explicit imports.

    Props & Events

    Props are passed from parent to child and are read-only within the child component.

    Validation

    Validation ensures props meet expected types and constraints. Failed validation throws a descriptive error in development mode.

    Event Emission

    For two-way communication, events are emitted upward through the component tree. Use the emit method with a payload.

    Slots

    Slots allow content composition. A default slot receives any content placed between the component tags.

    Default Slot

    Content not assigned to a named slot falls into the default slot automatically.

    Named Slots

    Named slots enable multiple insertion points. Use the slot attribute to target a specific named slot.

    Routing

    The router maps URLs to components with support for dynamic segments and nested routes.

    Basic Setup

    Create a router instance and define your routes as an array of route objects.

    Configuration

    Each route specifies a path pattern and the component to render. The router uses path-to-regexp for pattern matching.

    const router = createRouter({ routes: [ { path: '/', component: Home }, { path: '/about', component: About }, { path: '/user/:id', component: User } ] });

    History Mode

    Choose between hash mode and history mode. History mode requires server configuration to handle deep links.

    Programmatic Navigation

    Navigate imperatively using router instance methods. Useful for redirects after form submission.

    Push & Replace

    Use push to add a new history entry, or replace to navigate without adding to the history stack.

    Go & Back

    The go method accepts a delta integer. Positive values move forward, negative values move backward in history.

    Navigation Guards

    Guards intercept navigation and can prevent or redirect it.

    Global Guards

    Register beforeEach and afterEach hooks on the router instance to guard every navigation.

    Route-Level Guards

    Define beforeEnter directly on route definitions for guard logic scoped to a single route.

    State Management

    For complex applications, a centralized store helps manage shared state with unidirectional data flow.

    Creating a Store

    Define an initial state object and a set of mutations that modify that state.

    Store Definition

    Actions can contain asynchronous logic before committing mutations. Mutations must be synchronous.

    const store = createStore({ state: () => ({ count: 0 }), mutations: { increment(state) { state.count++; } } });

    Modules

    Split large stores into modules. Each module can have its own state, mutations, actions, and getters.

    Getters

    Getters compute derived state. They are cached and only re-evaluate when dependencies change.

    Basic Getters

    A getter receives the state as its first argument. Access it like a computed property.

    Parameterized Getters

    Return a function from a getter to accept arguments. These are not cached per parameter value.

    Actions

    Actions are similar to mutations but can contain asynchronous operations.

    Async Actions

    Dispatch an action, perform async work, then commit a mutation with the result.

    Action Composition

    Actions can dispatch other actions. This enables complex workflows built from simple primitives.

    Advanced Topics

    Patterns and techniques for building production-grade applications.

    Performance Optimization

    Virtual scrolling, lazy loading, and code splitting are built-in features.

    Bundle Size

    The compiler performs static analysis to eliminate dead code. Tree-shake unused exports to minimize bundle size.

    Render Optimization

    Use memo and shouldUpdate to prevent unnecessary re-renders. Profile with the built-in devtools.

    Testing

    Testing utilities provide helper functions for mounting components and asserting on rendered output.

    Unit Tests

    Mount a component in isolation, trigger events, and assert on the resulting DOM.

    test('button click increments counter', async () => { const wrapper = mount(Counter); await wrapper.find('button').trigger('click'); expect(wrapper.text()).toContain('1'); });

    E2E Tests

    Run end-to-end tests in a real browser environment. Use the test runner to automate user flows.

    Deployment

    Build for production with tree-shaking and minification.

    Static Hosting

    Static sites can be deployed to any CDN or static host. Pre-render routes for SEO benefits.

    Server-Side Rendering

    SSR requires a Node.js environment. Hydrate the client-side app on top of the server-rendered markup.
